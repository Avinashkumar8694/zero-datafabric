# Workbench Analytics & Query Guide

This document explains how to use Data Fabric Workbench for SQL and AST queries, including multi-source usage.

## 1. Workbench Modes

- SQL Mode: runs native SQL via `/api/queries/exec`.
- AST Mode: runs structured query config via `/api/analytics/query`.

## 2. Typical Workflow

1. Open `/workbench`.
2. Select source/schema/resource in Explorer.
3. Choose mode:
- SQL for direct querying.
- AST for guided, structured execution.
4. Pick Sync or Async run.
5. Review results grid and runtime status.

## 3. Multi-Source Query Patterns

### Pattern A: Federated SQL Query

Query federated tables/views generated by metadata apply:

```sql
SELECT sku, stock AS quantity, 'local' AS source
FROM "tenant_tenant_A_global_supply_chain"."local_inventory"
UNION ALL
SELECT item_id AS sku, qty AS quantity, 'remote' AS source
FROM "tenant_tenant_A_global_supply_chain"."remote_depot_mongo"
LIMIT 200;
```

### Pattern B: AST Join Query

Use manifest-style query AST (`query.from.resource`) for consistency with `test_manifest.json`:

```json
{
  "type": "SELECT",
  "schema": "Global_Supply_Chain",
  "limit": 100,
  "query": {
    "select": ["*"],
    "from": { "resource": "shipments", "source": "Fabric_Hub_Postgres" },
    "joins": [
      {
        "type": "INNER",
        "resource": "shipment_details",
        "source": "Fabric_Hub_Postgres",
        "on": { "left": "shipments.id", "operator": "EQ", "right": "shipment_details.shipment_id" }
      }
    ]
  }
}
```

### Pattern C: Recursive Query (SQL)

```sql
WITH RECURSIVE org_tree AS (
  SELECT id, manager_id, name, 1 AS depth
  FROM "tenant_tenant_A_global_supply_chain"."employees"
  WHERE manager_id IS NULL
  UNION ALL
  SELECT e.id, e.manager_id, e.name, ot.depth + 1
  FROM "tenant_tenant_A_global_supply_chain"."employees" e
  JOIN org_tree ot ON e.manager_id = ot.id
)
SELECT * FROM org_tree ORDER BY depth, name LIMIT 200;
```

## 4. Safety Guardrails

The engine blocks unrestricted operations:
- SELECT without LIMIT/WHERE may be blocked.
- UPDATE/DELETE without filter may be blocked.

Use explicit filter and/or limit for safe execution.

## 5. Async Query Use

For heavy queries:
- SQL async dispatch: `/api/queries/exec` with `{ "async": true }`
- AST async dispatch: `/api/analytics/query-async`
- Poll:
  - `/api/queries/jobs/:id`
  - `/api/analytics/jobs/:id`

## 6. Manifest-Driven Concepts Supported

Workbench supports querying artifacts generated from metadata apply:
- Tables
- Views / Materialized views
- Relationships (via joins)
- Recursive logic
- Federated patterns across heterogeneous sources

## 7. Complete Query Capability Examples

All examples below use the same `queryConfig` model used by `/api/analytics/query`.

### A. Basic SELECT (manifest-style)

```json
{
  "queryConfig": {
    "type": "SELECT",
    "schema": "Global_Supply_Chain",
    "limit": 20,
    "query": {
      "select": ["id", "region", "status"],
      "from": { "resource": "shipments", "source": "Fabric_Hub_Postgres" }
    }
  }
}
```

### B. Filter + Sort

```json
{
  "queryConfig": {
    "type": "SELECT",
    "schema": "Global_Supply_Chain",
    "limit": 50,
    "query": {
      "select": ["id", "status", "created_at"],
      "from": { "resource": "shipments" },
      "where": [
        { "column": "status", "operator": "EQ", "value": "PENDING" }
      ],
      "orderBy": [
        { "column": "created_at", "direction": "DESC" }
      ]
    }
  }
}
```

### C. Join Query

```json
{
  "queryConfig": {
    "type": "SELECT",
    "schema": "Global_Supply_Chain",
    "limit": 100,
    "query": {
      "select": ["shipments.id", "shipment_details.notes"],
      "from": { "resource": "shipments" },
      "joins": [
        {
          "type": "INNER",
          "resource": "shipment_details",
          "on": { "left": "shipments.id", "operator": "EQ", "right": "shipment_details.shipment_id" }
        }
      ]
    }
  }
}
```

### D. UNION / INTERSECT / EXCEPT

```json
{
  "queryConfig": {
    "type": "SELECT",
    "schema": "Global_Supply_Chain",
    "limit": 100,
    "query": {
      "union": [
        { "select": ["sku", "stock"], "from": { "resource": "local_inventory" } },
        { "select": ["item_id", "qty"], "from": { "resource": "remote_depot_mongo" } }
      ]
    }
  }
}
```

### E. Recursive CTE (engine-native)

```json
{
  "queryConfig": {
    "type": "SELECT",
    "schema": "Global_Supply_Chain",
    "table": "employees",
    "withRecursive": {
      "name": "org_tree",
      "baseQuery": "SELECT id, manager_id, name, 1 as depth FROM \"tenant_tenant_A_global_supply_chain\".\"employees\" WHERE manager_id IS NULL",
      "recursiveQuery": "SELECT e.id, e.manager_id, e.name, t.depth + 1 FROM \"tenant_tenant_A_global_supply_chain\".\"employees\" e INNER JOIN org_tree t ON e.manager_id = t.id"
    },
    "select": ["*"],
    "limit": 100
  }
}
```

### F. DML (INSERT / UPDATE / DELETE)

```json
{
  "queryConfig": {
    "type": "INSERT",
    "schema": "Global_Supply_Chain",
    "table": "shipment_details",
    "data": { "id": "00000000-0000-0000-0000-000000000001", "shipment_id": "00000000-0000-0000-0000-000000000002", "notes": "seed" }
  }
}
```

### G. Async Query Flow

1. `POST /api/analytics/query-async` with same `queryConfig`.
2. Poll `GET /api/analytics/jobs/:jobId`.
3. Use result payload when status becomes `COMPLETED`.

## 8. Elasticsearch Push Behavior

Current implementation:
- Elasticsearch indexing is executed during metadata apply (`/api/metadata/apply`).
- It creates/updates indices and pushes table rows for local hub resources.
- If ES is down, primary metadata apply continues (downstream reports degraded/error).

Not yet continuous:
- Insert/Update/Delete query execution does not currently stream every mutation to Elasticsearch in real-time.
- To reflect latest changes in ES immediately, re-run metadata apply (or implement CDC/event-based downstream sync in a next step).
