# Zero Data Fabric - Solution Architecture Document

## 1. Technology Stack
This end-to-end solution leverages open-source, enterprise-grade technologies aligned with your preferred stack:

*   **Frontend (Management UI & Dashboards):** Angular
*   **Backend Orchestration & Admin API:** Node.js + Express
*   **Data API Layer:** PostgREST (Auto-generates CRUD APIs directly from the database)
*   **Core Database Engine:** PostgreSQL (Version 16+)
*   **CDC & Event Streaming:** Debezium + Apache Kafka (or Redpanda)
*   **Database Extensions:** `postgres_fdw`, `mysql_fdw`, `mongo_fdw`, `citus` (Distributed), `pgvector` (AI), `pgaudit` (Compliance).

---

## 2. Module-Wise Solution Design

### Module 1: Data Integration, Virtualization & Sync
*   **Virtualization (Live Queries):** We will install Foreign Data Wrappers (`postgres_fdw`, `mysql_fdw`, `mongo_fdw`) inside PostgreSQL. The Node.js Admin API will expose endpoints for the Angular UI to dynamically configure these connections (e.g., submitting MySQL credentials via Angular, which Express encrypts and executes as a `CREATE SERVER` DDL in Postgres).
*   **CDC & Sync (Debezium):** For physical syncing, we will deploy Debezium. When a user configures a sync rule in the Angular UI, the Node.js backend sends a configuration payload to the Debezium Kafka Connect REST API, instructing it to tail the remote MongoDB Oplog and sink the data into a specific PostgreSQL table.

### Module 2: Advanced Query Engine & Analytics
*   **Distributed Scale:** We will enable the **Citus** extension on the PostgreSQL cluster to shard large analytical tables. 
*   **Querying:** Complex analytical queries (e.g., cross-system joins, recursive org-charts) will be encapsulated in PostgreSQL Stored Procedures. These procedures are automatically exposed as REST endpoints by **PostgREST**, which the Angular frontend can call securely.

### Module 3: Enterprise Security & Governance
*   **Row-Level Security (RLS):** When an Angular user logs in, the Node.js backend issues a JWT token containing their `tenant_id` and `role`. PostgREST reads this JWT natively and enforces RLS in PostgreSQL, ensuring the user only sees their allowed rows.
*   **Audit Logging:** We will install `pgaudit`. The logs will be routed to a dedicated `audit_logs` table, which the Angular UI can display for compliance officers.

### Module 4: Active Metadata & Cataloging
*   **Storage:** A central `metadata_catalog` schema in PostgreSQL will use `JSONB` to store dynamic data dictionaries, lineage paths, and quality scores.
*   **UI:** The Angular frontend will feature a "Data Discovery Portal" that queries this metadata schema via PostgREST, allowing users to search and tag datasets.

### Module 5: Multi-Tenancy & Isolation
*   **Schema Isolation:** When a new tenant is created via the Angular UI, the Express backend runs a script (via Flyway/Liquibase) to provision a dedicated `schema_tenant_xyz`. Connection pooling via **PgBouncer** ensures traffic is routed to the correct schema efficiently.

### Module 6: High Availability & Disaster Recovery
*   **HA:** The PostgreSQL cluster will be managed by **Patroni** for automated failover.
*   **DR:** Logical replication slots will be configured by the infrastructure layer to continuously stream WAL to a secondary region.

### Module 7: Automated API & Developer Portal
*   **Data API:** We completely bypass writing Express routes for basic CRUD. **PostgREST** sits directly on top of PostgreSQL, providing instant, blazing-fast REST APIs for all tables and views.
*   **Docs:** We will serve a **Swagger UI** container that automatically reads the OpenAPI spec generated by PostgREST, giving external developers a fully interactive playground.

### Module 8: Data Fabric Management UI
*   **Angular Implementation:** The frontend will be a massive Angular SPA comprising:
    *   *Connection Manager:* Form-driven UI to configure FDWs and Debezium CDC streams.
    *   *Visual Query Builder:* Drag-and-drop interface mapping to SQL generation.
    *   *Access Manager:* UI to approve/deny RLS roles.

### Module 9: Data Lineage & Quality Automation
*   **Quality Engine:** The Node.js Express backend will run scheduled cron jobs (using `node-cron` or BullMQ). These jobs execute SQL scripts to calculate null-rates and stale-data metrics, writing the results back to the metadata catalog.
*   **Lineage Visualizer:** The Angular UI will use a library like `ngx-graph` or `D3.js` to draw visual node-trees of data flow (Source -> FDW -> View -> Dashboard).

### Module 10: Developer Experience (IaC & GitOps)
*   **Backend Flow:** The Node.js backend will expose a Webhook endpoint (`POST /api/webhooks/github`). When developers push a schema change to GitHub, GitHub pings this Express route, which triggers a Liquibase/Flyway database migration to apply the DDL safely.

### Module 11: Event-Driven Webhooks & Push Data
*   **Real-time Push:** PostgreSQL `LISTEN/NOTIFY` triggers will be used. The Node.js Express backend will `LISTEN` to Postgres. When a critical data change occurs, Node.js catches the notification and emits it to the Angular frontend instantly using **Socket.io** (WebSockets) or triggers an external HTTP webhook.

### Module 12: AI & Machine Learning Readiness
*   **pgvector:** PostgreSQL will use `pgvector`. A Node.js microservice can be set up to listen to text inserts, call the OpenAI/Gemini API to generate embeddings, and save the vector array back into the database. The Angular UI can then offer "Semantic Search" alongside standard text search.

---

## 3. Recommended Phased Implementation
*   **Phase 1 (Foundation):** Set up Node.js, Express, PostgreSQL, PostgREST, and base Angular scaffold. Implement JWT + RLS.
*   **Phase 2 (Virtualization):** Implement FDWs and build the Angular UI to connect and query remote databases.
*   **Phase 3 (Sync & CDC):** Deploy Kafka/Debezium and build the UI to configure streaming rules.
*   **Phase 4 (Advanced Features):** Add pgvector, Webhooks, Lineage tracking, and GitOps pipelines.
